# CipherBox 客户端部署指南（Windows 10/11）

> 适用：员工 Windows 10/11 机器，接入已部署的 CipherBox 服务器（示例 `https://172.16.0.70:8443`）。
> 服务器部署见《[服务器部署指南-Ubuntu](服务器部署指南-Ubuntu.md)》。
> 本指南已按真实跨机环境验证（服务器 Ubuntu + 客户端 Win11 实测）。

## 0. 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| 系统 | Windows 10 / 11 | PowerShell 5.1（系统自带即可） |
| LibreOffice | 默认路径安装（`C:\Program Files\LibreOffice\`） | [zh.libreoffice.org](https://zh.libreoffice.org/) 下载装完再继续 |
| 网络 | 能访问服务器 8443 端口 | 测试: `curl.exe -sk https://172.16.0.70:8443/health` |
| 保密卷 | VeraCrypt 卷挂载为 `S:` | 测试机可临时用 `subst S: C:\某个空目录` 模拟 |
| 员工令牌 | 管理员线下分发的一串字符 | 见第 6 节"新员工入职" |
| 服务器 CA | 从服务器拷出的 `ca.crt` 文件 | 见第 3 节 |

> **不需要**装 Python——uv 会自动下载管理。

## 1. 获取代码

```powershell
git clone git@gitee.com:wanghannew1/cipher-box.git C:\cipherbox
cd C:\cipherbox
# 或下载 zip 解压到 C:\cipherbox（无 git 环境时）
```

## 2. 从服务器拷贝 CA 证书（防中间人，必做）

在**服务器**上执行并复制输出内容：

```bash
cat ~/github-src/cipher-box/server/certs/ca.crt
```

在**客户机**上把内容保存为文件（例如 `C:\cipherbox\config\ca.crt`，无 BOM 的纯文本即可；用记事本粘贴另存时编码选 ANSI 或 UTF-8 均可）。

## 3. 一键部署

```powershell
cd C:\cipherbox
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\client_setup_uv.ps1 `
    -ServerUrl https://172.16.0.70:8443 `
    -CaCertFile C:\cipherbox\config\ca.crt `
    -EmployeeToken <管理员发的员工令牌> `
    -Associate
```

（`-EmployeeToken` 不加参数则隐藏输入；`-Associate` 注册 .cbx 双击关联，HKCU 免管理员）

脚本自动完成并逐行打印：

| 步骤 | 内容 | 幂等策略 |
|---|---|---|
| 1 | 检查/安装 uv（国内镜像内置） | 已装跳过 |
| 2 | `uv venv agent\.venv` + 装依赖 | 已存在跳过（`-Recreate` 重建） |
| 3 | 前置检查：LibreOffice / S: 卷 / LO 自带 Python | 缺失即报错并给指引 |
| 4 | 服务器探活 | 不可达仅警告不阻断 |
| 5 | 写 `config\client.json`（9 个键） | 每次按参数重写 |
| 6 | DPAPI 加密员工令牌 → `config\employee_token.dpapi` | 令牌经 stdin 传递，不落命令行 |
| 7 | 生成 `deploy\cbx_open.cmd` + （`-Associate`）注册 .cbx 关联 | 内容不变则跳过 |

**成功标志**：`[setup] 客户端部署完成`，且 `config\employee_token.dpapi` 存在。

## 4. 一键启动

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\client_start.ps1
```

会弹出**独立 Agent 控制台窗口**（保持开启），依次出现四行即成功：

```
[agent] recovery: ...                     ← 崩溃恢复（最先）
[agent] keys: 1 version(s), current=v1    ← 从服务器取钥（断网自动用本地缓存）
[agent] watcher: started on S:\           ← 监控启动
[agent] pipe: listening on \\.\pipe\cipherbox-open
```

停止：`deploy\client_stop.ps1`（只停 Agent 和加密服务进程，不误伤其它程序）。

## 5. 部署后验证清单

| # | 测试 | 期望 |
|---|---|---|
| 1 | 复制一份明文 `docx` 到 `S:\` 下任意目录 | 约 10 秒后明文消失、出现 `<原名>.docx.cbx` |
| 2 | 双击该 `.cbx`（已 `-Associate`）或 `agent\.venv\Scripts\python.exe -m agent.launcher <文件.cbx>` | LO 打开明文；编辑保存后关闭，`.cbx` 自动更新、临时明文消失 |
| 3 | 请管理员在服务器查 `GET /events` | 能看到你的 encrypt/decrypt 事件（employee=你的令牌名） |
| 4 | 断网重开一个 .cbx | 仍能打开（密钥本地缓存）；审计事件暂存本地，联网后自动补报 |

## 6. 新员工入职（管理员操作）

在**服务器**上为每位员工签发令牌并线下分发（IM 当面发，勿走群聊）：

```bash
server/.venv/bin/python deploy/seed_local.py --db server/cipherbox.db \
    --hmac-out server/audit-hmac.key --employee-name zhangsan
# 只取输出里的 employee token；hmac 密钥文件已存在会自动保留（审计链不断）
```

员工拿到令牌后按本指南第 3 节部署即可。令牌泄露时管理员调 `POST /admin/revoke` 吊销。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| `unable to get local issuer certificate` | 客户端 CA 与服务器不匹配：服务器重签过证书后，**必须重新拷贝新 ca.crt** 并更新 `client.json` 的 `ca_cert_file` 指向 |
| 证书校验报主机名不匹配 | 服务器重签时必须带 `--san IP:<服务器IP>`（见服务器指南"双机部署要点"） |
| `未找到 uv` | 加 `-InstallUv` 重跑；企业内网装不上时手动下载 uv 放 `~/.local/bin` |
| `UNO subprocess failed` | LO 不在默认路径：设系统环境变量 `CIPHERBOX_LO_PYTHON` 指向 LO 的 `python.exe` |
| 保密卷未挂载报错 | 挂载 VeraCrypt 卷到 `S:`；未挂载期间 Agent 会拒绝启动（防误写） |
| Agent 窗口一闪而过 | 用 `client_start.ps1` 启动（带 -NoExit 窗口保留报错信息）；常见原因：令牌文件缺失/服务器不可达 |
| 401 | 令牌被吊销/过期，找管理员重发 |
| 审计事件没到服务器 | 已暂存本地（DPAPI 加密），联网后 Agent 启动自动补报 |

## 8. 边界声明（如实）

- 受控打开的 LO 会话内，"另存为明文/PDF 导出"**暂不被强制拦截**（拦截器本体已实现并验证，接入受控会话是下一期工作）——请依赖管理制度约束该行为。
- 受控会话的结束判定是 LO 进程退出（关掉 Start Center 才结束），非文档级事件。
- `.cbx` 密文离开 `S:` 卷后任何人（包括你自己）都需要通过本系统才能打开——这是设计目标。
