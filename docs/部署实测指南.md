# CipherBox 单机实测指南

> 适用：在这台开发机上把"服务器 → Agent → LibreOffice 加密/受控打开"全链路真实跑一遍。
> 2026-11-02 生成，所有命令均已在本机验证过对应环节。
> **员工真实客户机的部署请用《[客户端部署指南](客户端部署指南.md)》**（本指南是开发机单机联调视角）。
> 生产双机部署（`deploy/server_bootstrap.ps1` + `install.ps1`）尚有占位项，本指南为**单机手动实测**流程。

## 0. 前置条件（本机已具备）

| 组件 | 位置/版本 | 用途 |
|---|---|---|
| Python（主环境） | anaconda 3.11.7，含 watchdog/olefile/requests | 服务器 + Agent |
| LibreOffice | `C:\Program Files\LibreOffice\`，自带 Python 3.13（含 uno） | 加密引擎 + 编辑器 |
| OpenSSL | PATH 中 3.0.15 | 生成自签证书 |
| 测试卷 | `subst S: C:\code\cipherbox\.s-volume`（模拟 VeraCrypt 卷） | 受保护区域 |

**关键机制**：主 Python 加载不了 pyuno（版本锁死 3.13），Agent 的加密操作会**自动委托**给 LO 自带 Python 子进程（`agent/uno_subprocess.py`，口令走 stdin 不上命令行）。若 LO 装在非默认路径，设置环境变量 `CIPHERBOX_LO_PYTHON` 指向其 `python.exe`。

## 1. 环境准备（每次开机后执行一次）

```powershell
cd C:\code\cipherbox
# 1a. 测试卷（真实部署用 VeraCrypt 挂载 S:）
if (-not (Test-Path 'S:\')) { subst S: 'C:\code\cipherbox\.s-volume' }

# 1b. 常驻 LO 加密服务（管道 cipherbox-service）
powershell -NoProfile -ExecutionPolicy Bypass -File lo-encryption-demo\start_soffice.ps1
# 期望输出: service ready: uno:pipe,name=cipherbox-service;urp;... resolves

# 1c. 受保护目录（模拟保密盘里的工作区）
New-Item -ItemType Directory -Force -Path 'S:\test-docs' | Out-Null
```

## 2. 启动服务器

> **一键方式（推荐）**：`powershell -NoProfile -ExecutionPolicy Bypass -File deploy\server_setup_uv.ps1`
> （uv 虚拟环境 + 证书 + 种子库一步完成，幂等可重跑；详细说明见《[服务器部署指南](服务器部署指南.md)》）。
> 之后日常启动用 `deploy\server_start.ps1` 代替下面 2c 的手动命令。以下为等效手动步骤。

```powershell
# 2a. 首次：生成自签 CA + 服务器证书（已有则跳过；--force 重新生成）
server\.venv\Scripts\python.exe deploy\gen_certs.py

# 2b. 首次：种子数据库 + HMAC 审计密钥（两个令牌只打印一次，立刻保存！）
python deploy\seed_local.py --db server\cipherbox.db --hmac-out server\audit-hmac.key
# 输出:
#   [seed] admin token (shown ONCE ...):    <ADMIN_TOKEN>
#   [seed] employee token (shown ONCE ...): <EMPLOYEE_TOKEN>

# 2c. 启动（新开一个终端窗口，保持运行）
cd C:\code\cipherbox
$env:CIPHERBOX_HMAC_KEY_FILE = "$PWD\server\audit-hmac.key"
server\.venv\Scripts\python.exe -m uvicorn server.app:create_app --factory `
    --host 127.0.0.1 --port 8443 `
    --ssl-certfile server\certs\server.crt --ssl-keyfile server\certs\server.key

# 2d. 健康检查（另开终端）
curl.exe -k https://127.0.0.1:8443/health
# 期望: {"status":"ok"}
```

## 3. 客户端配置（Agent 用）

```powershell
# 3a. DPAPI 加密员工令牌（当前 Windows 用户可解；换用户需重做）
New-Item -ItemType Directory -Force -Path config | Out-Null
python -c "import sys; sys.path.insert(0, r'C:\code\cipherbox'); from agent.key_manager import dpapi_encrypt; open(r'config\employee_token.dpapi','wb').write(dpapi_encrypt(b'<把这里换成EMPLOYEE_TOKEN>'))"

# 3b. 写 config\client.json（9 个键，单机实测值如下）
@'
{
  "server_url": "https://127.0.0.1:8443",
  "ca_cert_file": "C:/code/cipherbox/server/certs/ca.crt",
  "protected_dir": "S:/test-docs",
  "temp_root": "S:/.cipherbox-tmp",
  "service_profile": "S:/.cipherbox-profile/service",
  "controlled_profile": "S:/.cipherbox-profile/controlled",
  "session_dir": "C:/code/cipherbox/.s-volume/.agent-sessions",
  "keycache": "C:/code/cipherbox/.s-volume/.agent-keycache.dat",
  "audit_queue": "C:/code/cipherbox/.s-volume/.agent-audit-queue.json"
}
'@ | Set-Content config\client.json -Encoding Ascii
```

> 注意：JSON 里不要用 PowerShell 5.1 默认 UTF8 写（会带 BOM，加载器已兼容 `utf-8-sig`，但 Ascii 最稳）。路径用正斜杠。

## 4. 启动 Agent（新开终端，保持运行）

```powershell
cd C:\code\cipherbox
python -m agent --config config\client.json --token-file config\employee_token.dpapi
# 期望输出顺序（计划规定的启动顺序）:
#   [agent] recovery: queue_files_replayed=0 ...          ← 崩溃恢复最先
#   [agent] keys: 1 version(s), current=v1                ← 服务器在线取钥
#   [agent] watcher: started on S:\test-docs              ← 监控启动
#   [agent] pipe: listening on \\.\pipe\cipherbox-open    ← 受控打开入口
```

首次启动需要服务器在线（取钥并写 DPAPI 缓存 `keycache`）。之后断网可用缓存。
**重复启动会被单实例互斥体拒绝**（`another resident agent already owns the instance mutex`），这是预期行为。

## 5. 实测 A：监控自动加密（落盘即密文）

```powershell
# 放一份明文 docx 进受保护目录（仓库自带真实明文夹具）
Copy-Item agent\tests\fixtures\reencrypted.docx.plain S:\test-docs\sample.docx
# 等 5 秒防抖 + 加密
Start-Sleep -Seconds 8
Get-ChildItem S:\test-docs
# 期望: sample.docx 消失, sample.docx.cbx 出现
# Agent 终端同步打印 encrypt 审计上报
```

验证密文不是伪加密：
```powershell
$b = [System.IO.File]::ReadAllBytes('S:\test-docs\sample.docx.cbx')[0..3]
($b | ForEach-Object { $_.ToString('x2') }) -join ' '   # 期望 d0 cf 11 e0（OLE 容器）
```

## 6. 实测 B：双击受控打开闭环

```powershell
python -m agent.launcher S:\test-docs\sample.docx.cbx
```

1. 会弹出一个独立的 LibreOffice 窗口打开明文（受控专用 profile，`TMP/TEMP` 指向卷内会话目录）。
2. 随便编辑一下（打几个字），**保存后关闭整个 LO 窗口**。
3. launcher 打印 `{"changed": true, "re_encrypted": true, "ok": true}` —— 临时明文已删、`.cbx` 已用当前密钥重加密。
4. 再次运行 launcher 可重新打开，确认你的编辑还在（密文往返成立）。

> 边界声明（如实）：本最小版受控会话**未接入强制加密拦截器**——会话内"另存为明文/导出 PDF"暂不被拦截或审计（拦截器本体已修复并冒烟通过，接入受控流程是下一步 todo 17 接线）。**关闭窗口前先正常保存**，不要依赖会话内强制加密。

## 8. 实测 D：审计链防篡改校验

```powershell
python -m server.verify_audit server\cipherbox.db server\audit-hmac.key
# 期望: OK: audit chain verified (N events)
# 篡改实验: 用 sqlite3 改任何一行再跑 → FAIL 并定位行号; 删尾部再伪造链头 → 仍 FAIL（运行链不可重放）
```

## 9. 常见问题

| 现象 | 原因/处理 |
|---|---|
| Agent 报 `unable to get local issuer certificate` | 客户端固定 CA 与服务器不匹配。**同机测试注意**：`server\certs\ca.crt` 既是本地服务器 CA 又被当客户端 CA——服务器重签后需重新拷贝覆盖；推荐把服务器 CA 放独立路径（如 `config\ca-vodserver.crt`）并让 `client.json` 的 `ca_cert_file` 指向它，避免两套身份互相覆盖 |
| 审计事件没落服务器 | 上报失败会暂存 `%APPDATA%\CipherBox\audit-queue.json`（DPAPI 加密），Agent 联网启动时自动补报（窗口会打印 `audit: replayed N queued event(s)`） |
| Agent 起不来 `keys: unavailable` | 服务器没起或令牌错。先起服务器；令牌错就重做 3a |
| `config error: ... not valid` | client.json 缺键/格式错；对照 3b 的 9 个键 |
| 加密报 `UNO subprocess failed` | LO 不在默认路径 → 设 `$env:CIPHERBOX_LO_PYTHON` 指向其 python.exe；或 LO 服务没起 → 重跑 1b |
| watcher 不加密 | 只认 `.docx/.xlsx/.pptx`；防抖 5 秒；排除 `.cbx`/`.cipherbox-*`/LO 锁文件；LO 正在编辑（锁文件存在）会跳过等待 |
| `busy: another controlled session is active` | 上一个受控会话未结束，关闭 LO 窗口后重试 |
| launcher 报 agent 不可达 | Agent 没起；launcher 会自动拉起一次，10 秒内连不上才报错 |
| 401 | 令牌过期/吊销；用 admin 令牌调 `/admin/revoke` 的反面 = 重新 seed |

## 10. 已知边界（本期如实声明）

1. 受控会话无拦截器（见 6 的声明）；会话期明文临时副本落在卷内 `S:\.cipherbox-tmp\<会话>\`（设计边界）。
2. 关闭检测 = 等 LO 进程退出（非文档级 XModel 事件）——关掉 Start Center 才算会话结束。
3. `deploy/*.ps1` 的开机自启/ACL/LO 加固是占位符，本指南即手动部署流程。
4. 单机实测 = 服务器和客户端同机；双机验收（F3）需真实两台机器。
