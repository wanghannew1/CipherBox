# CipherBox 服务器部署指南（uv 版）

> 目标：在一台 Windows 机器上把密钥/审计服务器部署到**可直接使用**。
> 推荐方式一（一键，幂等可重复执行）；方式二为等效手动步骤，供理解与排障。
> 部署完成后回到《[部署实测指南](部署实测指南.md)》继续客户端实测。

## 方式一：一键部署（推荐，傻瓜式）

```powershell
cd C:\code\cipherbox
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\server_setup_uv.ps1
```

脚本自动完成（**重复执行安全**，每步已完成的自动跳过）：

| 步骤 | 内容 | 幂等策略 |
|---|---|---|
| 1 | 检查 uv | 缺失时报错（加 `-InstallUv` 自动安装） |
| 2 | `uv venv` 创建 `server\.venv`（Python 3.11） | 已存在则跳过（`-Recreate` 重建） |
| 3 | `uv pip install -r server\requirements.txt` | 按 pin 解析，秒级 |
| 4 | `gen_certs.py` 自签 CA + 服务器证书（需 OpenSSL 在 PATH） | `server\certs\server.crt` 已存在则跳过 |
| 5 | `seed_local.py` 建库 + 种子 admin/employee 令牌 + 32 字节 HMAC 审计密钥 | `server\cipherbox.db` 已存在则跳过（`-Reseed` 重新签发） |
| 6 | 打印日常启动/健康检查命令 | — |

**重要输出**：两个明文令牌**只打印一次**，当场保存：

```
[seed] admin token (shown ONCE ...):    <ADMIN_TOKEN>
[seed] employee token (shown ONCE ...): <EMPLOYEE_TOKEN>
```

丢失处理：`-Reseed` 重新签发（旧令牌仍有效，正式环境建议先调 `/admin/revoke` 吊销）。

## 方式二：手动分步（等效）

```powershell
cd C:\code\cipherbox

# 1. 安装 uv（已装跳过）
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# 2. 虚拟环境 + 依赖（uv 管理，全部锁在 server\.venv 内）
uv venv server\.venv --python 3.11
uv pip install --python server\.venv\Scripts\python.exe -r server\requirements.txt

# 3. 自签证书（CA + 服务器证书，SAN= DNS:localhost / IP:127.0.0.1）
server\.venv\Scripts\python.exe deploy\gen_certs.py          # 加 --force 重新生成

# 4. 种子数据库 + HMAC 密钥
server\.venv\Scripts\python.exe deploy\seed_local.py --db server\cipherbox.db --hmac-out server\audit-hmac.key
```

## 日常运维

```powershell
# 启动（前台运行，Ctrl+C 停止；只绑 TLS，无 HTTP 端口）
powershell -NoProfile -ExecutionPolicy Bypass -File deploy\server_start.ps1
# 自定义端口: deploy\server_start.ps1 -Port 9443

# 健康检查
curl.exe -k https://127.0.0.1:8443/health        # {"status":"ok"}

# 审计链完整性校验（0=通过）
server\.venv\Scripts\python.exe -m server.verify_audit server\cipherbox.db server\audit-hmac.key

# 查审计事件（admin 令牌）
curl.exe -k -H "Authorization: Bearer <ADMIN_TOKEN>" "https://127.0.0.1:8443/events"
```

## 局域网开放（双机部署时）

```powershell
# 防火墙放行 8443（管理员）
netsh advfirewall firewall add rule name="cipherbox-8443" dir=in action=allow protocol=TCP localport=8443

# 服务器启动监听 0.0.0.0（server_start.ps1 默认即是）
# 客户端 config\client.json:
#   "server_url": "https://<服务器IP>:8443",
#   "ca_cert_file": "<从服务器拷来的 server\certs\ca.crt 路径>"   ← 客户端 pin 这个 CA
```

## 开机自启（可选，简易版）

```powershell
# 管理员执行一次；开机延迟 30 秒自动拉起服务器
schtasks /Create /TN "CipherBoxServer" /SC ONSTART /DELAY 0000:30 /RU SYSTEM ^
  /TR "powershell -NoProfile -ExecutionPolicy Bypass -File C:\code\cipherbox\deploy\server_start.ps1"
# 删除: schtasks /Delete /TN "CipherBoxServer" /F
```

> 计划 todo 20 的完整引导（专用服务账户 + ACL 收紧 + 注册表级自启）仍是占位符；以上为可用的简化版。

## 常见问题

| 现象 | 处理 |
|---|---|
| 浏览器访问 `https://<IP>:8443/` 返回 `{"detail":"Not Found"}` | **正常**——纯 API 服务无网页，能收到这个 JSON 恰好证明 TLS 和访问是通的。健康检查用 `/health` |
| `未找到 uv` | 重跑加 `-InstallUv`，或手动 `irm https://astral.sh/uv/install.ps1 \| iex` |
| `未找到 openssl` | 装 OpenSSL（如 winget install ShiningLight.OpenSSL.Light）后重跑 |
| 端口被占（启动报 WinError 10048） | `netstat -ano \| findstr :8443` 找 PID 结束，或 `-Port 9443` |
| 健康检查连接拒绝 | 服务器没起；看启动窗口的 traceback |
| 401 | 令牌错/过期/吊销；`-Reseed` 重签 |
| PowerShell 运行 .ps1 报乱码解析错误 | 本仓库中文脚本已带 UTF-8 BOM；自行新建 .ps1 含中文时务必存成 UTF-8 with BOM |
| 客户端报证书校验失败 | 确认客户端 `ca_cert_file` 指向服务器导出的 `ca.crt`，且 `server_url` 主机名/IP 与证书 SAN 一致（本地默认 SAN 只含 localhost/127.0.0.1，双机部署需 `--force` 重新生成含服务器 IP 的证书——改 `deploy\gen_certs.py` 的 SAN 列表） |

## 安全须知

- `server\certs\*.key`、`server\audit-hmac.key`、`server\cipherbox.db` 均在 `.gitignore` 内，**不入库**。
- 正式环境：HMAC 密钥与私钥文件 ACL 收紧到"运行账户 + 管理员"（todo 20 ⑥ 完整版待补）。
- 令牌明文只出现一次；泄露立即 `-Reseed`（测试）或 `/admin/revoke`（正式）。
- 主密钥目前明文存 DB（计划要求的运行账户 DPAPI 包裹为已登记缺口，见交接文档 v2）。
