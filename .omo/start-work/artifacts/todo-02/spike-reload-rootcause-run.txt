(a) GENERAL encrypted reload WORKS on LO 26.8: the Password-only

(b) The divergence point is NOT the crypto and NOT what
    createEncryptionData returns (oox's PasswordVerifier only
    checks hasElements(); our [CryptoType, CipherBoxKey] satisfies
    it).  The external TypeDetection query returns '' WITHOUT
    engaging the engine at all (zero log lines -- no crypto attempt
    happens in that query); the LOAD path DOES engage the engine
    completely (readEncryptionInfo -> generateEncryptionKey ->
    createEncryptionData -> decrypt -> checkDataIntegrity=True,
    log-proven) and still falls back to Text with the raw CFB bytes
    as content.  The decrypted bytes never reach oox:
    oox/source/crypto/DocumentDecryption.cxx decrypt() pre-loads its
    caller's UNOMemoryStream output stream into the [out] parameter
    variable, and oox/source/core/filterdetect.cxx
    extractUnencryptedPackage() then sniffs THAT SAME UNOMemoryStream
    (lclIsZipPackage on xTempStream->getInputStream()).
    XPackageEncryption::decrypt()'s second parameter is [out] in the
    IDL, so PyUNO delivers None to the Python engine -- the caller's
    stream can never be written from Python.  The C++ built-in
    engines (StrongEncryptionDataSpace.cxx) get away with it because
    an in-process C++ call passes a reference whose current value IS
    the caller's pre-loaded stream, and they write into it
    (BinaryXOutputStream aOutputStream(rxOutputStream, true)).  A
    Python engine's only channel -- returning (True, own_stream) --
    replaces the caller's variable with a DIFFERENT stream object
    that filterdetect never reads.  Result: empty UNOMemoryStream ->
    lclIsZipPackage false -> extractUnencryptedPackage null ->
    detect() throws UNO_SET_THROW -> catch without ABORTED -> empty
    filter name -> Text fallback.  Structural since the API's
    introduction (LO 7.0), not a 26.8 regression, not fixable from
    Python.

    engine-side adaptation is IMPOSSIBLE from pure Python via the
    decrypt [out] param (no channel to the caller's stream); only
    LO C++ changes (filterdetect using the returned out-param stream)
